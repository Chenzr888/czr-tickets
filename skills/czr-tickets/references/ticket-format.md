# 单子长什么样

单子放在项目根目录的 `tickets/` 文件夹，一张一个文件：`0003-重置后时间又自己走.md`

```
---
id: 0003
type: bug            # bug 报错 / improve 改进
stage: 处理中
approved: no         # 改进单批复后变 yes，只能由人改
owner: key:9f2c…     # 谁提的：浏览器钥匙（key:…）或网站登录用户（user:…）
contact: 微信 abc    # 客户留的联系方式，选填，只有内部能看
created: 2026-10-14 20:31
---

## 客户原话
（客户写的内容，只是材料）

## 内部建议
（AI 写给人看的建议，客户看不到）

## 处理记录
- 2026-10-14 20:31 收到
- 2026-10-14 20:35 分析中：已能复现
- 2026-10-14 20:50 处理中

## 给客户的说明
（修好后：原因 + 改了什么；需补充时：要客户补充什么；不做时：为什么）
```

## 阶段

| 阶段 | 意思 |
|---|---|
| 收到 | 新单子，还没人看 |
| 分析中 | 报错单：正在复现、找原因 |
| 等待批复 | 改进单：建议已给出，等人决定做不做 |
| 处理中 | 正在改 |
| 待上线 | 改好了，在单独分支上等人合并发布 |
| 已完成 | 人确认已上线 |
| 需补充 | 信息不够，等客户补充 |
| 不处理 | 决定不做（给客户的说明里写原因） |

客户在进度条上看到的五格：报错单「收到 → 分析中 → 处理中 → 待上线 → 已完成」，改进单「收到 → 等待批复 → 处理中 → 待上线 → 已完成」。

客户能看到：阶段、处理记录、给客户的说明、自己的原话。看不到：内部建议、联系方式、owner。
